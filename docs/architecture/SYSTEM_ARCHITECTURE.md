## 🎯 Architecture Layers

### 1. **Frontend Layer** (Browser)
**Location**: `/public/static/`

**Components**:
- **HTML Rendering**: Generated by Hono in `src/index.tsx`
- **JavaScript Modules**:
  - `app-simplified.js` - Dashboard data loading
  - `tab-system.js` - Tab navigation logic
  - `report-case-form.js` - Form submission
  - `view-cases.js` - Case browsing
  - `district-map.js` - Geographic visualization
  - `rainbo-dashboard.js` - Medical portal
  - `police-dashboard.js` - Police portal

**Technologies**:
- Vanilla JavaScript (no framework)
- Tailwind CSS (utility-first styling)
- Chart.js (data visualization)
- Axios (HTTP requests)

**Key Features**:
- Single Page Application (SPA) behavior with tabs
- Real-time chart updates
- Form validation
- Session management

---

### 2. **Backend Layer** (Cloudflare Workers)
**Location**: `src/index.tsx`

**Framework**: Hono (lightweight, fast)

**API Endpoints**:

```typescript
// Statistics
GET /api/stats
  → Returns dashboard statistics

// Districts
GET /api/districts
  → Returns all 16 districts with case counts

// Cases
GET /api/cases
  → Returns all cases (with pagination)
  → Query params: page, limit, district, type, status

POST /api/cases
  → Create new case
  → Body: reporter info, incident details, survivor info

// Authentication
POST /api/auth/login
  → Login to portals (Rainbo/Police)
  → Body: username, password
  → Returns: session_id, user info

// Service Providers
GET /api/service-providers
  → Returns all service provider organizations
```

**Middleware**:
- CORS (Cross-Origin Resource Sharing)
- Session validation
- Error handling

**Key Features**:
- RESTful API design
- Type-safe with TypeScript
- Serverless (no server management)
- Global edge deployment

---

### 3. **Database Layer** (Cloudflare D1)
**Type**: SQLite (globally distributed)

**Schema**: See [DATABASE_SCHEMA.md](DATABASE_SCHEMA.md)

**Key Tables**:
- `districts` - Geographic regions
- `gbv_cases` - Case records
- `gbv_types` - Violence categories
- `service_providers` - Organizations
- `users` - Portal accounts
- `sessions` - Authentication

**Features**:
- ACID transactions
- Foreign key constraints
- Indexed queries
- Automatic replication

## 🔄 Request Flow

### Example: Loading Dashboard Statistics

```
1. User opens dashboard
   ↓
2. Browser loads HTML from Hono
   ↓
3. JavaScript (app-simplified.js) executes
   ↓
4. Axios makes request: GET /api/stats
   ↓
5. Hono receives request at Worker
   ↓
6. Worker queries D1 database:
   • SELECT COUNT(*) FROM gbv_cases
   • SELECT district, COUNT(*) FROM gbv_cases GROUP BY district
   • SELECT gbv_type, COUNT(*) FROM gbv_cases GROUP BY gbv_type
   ↓
7. D1 returns query results
   ↓
8. Hono formats JSON response
   ↓
9. Cloudflare Edge caches response (optional)
   ↓
10. Browser receives JSON data
   ↓
11. Chart.js renders visualizations
   ↓
12. User sees dashboard statistics
```

### Example: Submitting a Case

```
1. User fills out form in Report Case tab
   ↓
2. User clicks "Submit Report"
   ↓
3. JavaScript validates form (report-case-form.js)
   ↓
4. Axios posts data: POST /api/cases
   ↓
5. Hono receives request at Worker
   ↓
6. Worker validates data
   ↓
7. Worker generates case number (GBV-2025-XXXX)
   ↓
8. Worker inserts into D1 database:
   INSERT INTO gbv_cases (...)
   ↓
9. D1 confirms insert successful
   ↓
10. Hono returns success response with case number
   ↓
11. Browser shows success message
   ↓
12. User sees case number
```

## 🔐 Security Architecture

### Authentication Flow
```
1. User enters credentials in portal
   ↓
2. POST /api/auth/login
   ↓
3. Server queries users table
   ↓
4. Password verification (plaintext for now - TODO: bcrypt)
   ↓
5. Generate session UUID
   ↓
6. Store in sessions table with expiration
   ↓
7. Return session_id to browser
   ↓
8. Browser stores in sessionStorage
   ↓
9. Include session_id in subsequent requests
```

### Data Protection
- **Anonymization**: Survivor names not stored
- **HTTPS**: All connections encrypted
- **CORS**: Restricted cross-origin requests
- **Sessions**: Time-based expiration
- **Environment Variables**: Secrets in .dev.vars (not committed)

## 🎯 Design Principles

### 1. **Serverless-First**
- No server management
- Auto-scaling
- Global edge deployment
- Pay-per-use

### 2. **Type Safety**
- TypeScript everywhere
- Compile-time error catching
- Better IDE support

### 3. **API-First**
- Clear RESTful endpoints
- JSON responses
- Versioned (future-ready)

### 4. **Progressive Enhancement**
- Works without JavaScript (HTML fallback)
- Enhanced with JavaScript
- Responsive design

### 5. **Security by Default**
- HTTPS everywhere
- No sensitive data in frontend
- Session-based auth
- Input validation

## 📈 Performance Characteristics

**Response Times**:
- Static assets: ~10-20ms (edge cache)
- API calls: ~50-100ms (database query + response)
- First page load: ~200-300ms
- Subsequent navigation: ~50ms (SPA)

**Scalability**:
- Handles thousands of concurrent users
- Auto-scaling at edge
- No single point of failure
- Global distribution
